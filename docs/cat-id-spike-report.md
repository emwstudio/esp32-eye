# 1B 认猫能力实测报告（阶段 2 spike 结论）

日期：2026-10-21
测试对象：baobao（橘色虎斑）、bobo、qiuqiu、shandian（后三只均为浅色系，外观相似）
方法：`server/tools/cat_id_spike.py`，每只猫留 1-2 张照片作考题、其余作参考，多图 prompt 询问模型。

## 结果汇总

| 模型 | 策略 | 准确率 | 备注 |
|---|---|---|---|
| 1B Q4_K_M（本地） | 四选一多图 | 25% | 全体答案塌缩为 shandian |
| 1B F16（本地） | 四选一多图 | 50% | baobao、shandian 对；bobo↔qiuqiu 混 |
| 1B F16（本地） | 逐只二选一（2 参考图） | 75% (3/4) | shandian 多票不确定 |
| 1B F16（本地） | 逐只二选一（3 参考图，8 考题） | 38% (3/8) | 仅 baobao 全对；浅色三猫全部多票 |
| **35B-A3B（云端）** | **四选一多图（直答）** | **100% (8/8)** | zh_direct + en_direct 均 4/4 |

（zh_reason prompt 的低分是答案解析伪影：模型先复述候选名，parse 取第一个出现的名字所致，不代表模型能力。）

## 结论

1. **任务形态 > 模型档位**：四选一多图对比超出 1B 注意力容量；逐只二选一显著提升，但 1B 对相似猫"不会拒绝"（凡浅色猫都投"是"）。
2. **1B 的能力边界**：能稳定辨认特征鲜明的猫（baobao 橘虎斑 2/2）；对 bobo/qiuqiu/shandian 三只浅色撞脸猫无可靠区分能力。其"是"票召回率高，可作粗筛信号，不可作定案。
3. **云端 35B 四选一 100%**：生产身份确认链路（本地 1B 门控 + 云端 35B 认猫）验证成立。

## 架构决策（据此固化）

- **门控（喝水检测）**：本地 1B，Q4_K_M 档（速度优先，~1.4s/帧）。
- **身份确认**：云端 35B-A3B，多图四选一直答式 prompt（zh_direct 风格，JSON 输出）。
- **云端不可用时**：事件保持 confirming 并自动重试（最多 3 次退避），恢复后补识别；不做 1B 离线认猫降级（实测它对相似猫不可靠，不如不认）。
- 参考照片策略：每只猫 3 张参考图参与推理（信息足够且控制 prompt 体积）。
